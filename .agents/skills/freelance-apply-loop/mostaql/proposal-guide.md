# Mostaql proposal guide (نص العرض)

Read [`../../candidate-source.md`](../../candidate-source.md), then write offers only from the current `resume.tex`. Default language: **Arabic** as a platform-writing choice, not a language-proficiency claim. Short, specific, respectful.

## Length

~80–180 كلمة ما لم يطلب المشروع تفصيلًا أطول.

## Structure (Arabic)

1. **افتتاح (جملة–جملتان):** اربط المشكلة بحلّك (التقنية + النتيجة) — لا سيرة طويلة.
2. **إثبات ملاءمة (٢–٣ نقاط):** Example Travel Platform / حجز B2B / Angular migration / Next.js SSR — فقط ما يطابق المشروع.
3. **خطة مختصرة (٢–٤ خطوات):** فهم المتطلبات → مراجعة الواجهة/الـ API → تسليم شريحة أولى قابلة للمراجعة → تحسينات.
4. **خاتمة:** جاهزية للتوضيح عبر نقاش المشروع + سؤال واحد إن لزم.

## Tone

- مهني، مباشر، واثق — بدون مبالغة أو إيموجي مفرط
- عربية فصحى مبسطة مفهومة لأصحاب المشاريع
- أبرز الوضوح والملكية على النتيجة (بدون حشو كلمات مفتاحية)

## Writing voice (required)

Follow [../../website-apply-loop/writing-voice.md](../../website-apply-loop/writing-voice.md). Verbatim rules:

Mix sentence lengths: Combine short, punchy sentences with longer, multi-clause ones instead of keeping every sentence uniform.

Add specific details: Swap abstract, clinical terms for concrete examples, textures, or real-world scenarios.

Vary paragraph structure: Break up predictable paragraph sizes and avoid using a textbook topic sentence for every single paragraph.

Write conversationally: Read your text out loud and replace stiff, formal phrasing with words you would actually say out loud.

Cut the fluff: Remove redundant transitions, repetitive over-explanations, and unnecessary summaries.

## Never

- اختلاق خبرات أو أدوات أو سنوات
- نسخ نفس العرض لكل مشروع
- لصق الـ CV كاملًا
- وعود زمنية غير واقعية
- روابط خارجية إن رفضتها المنصة — صف العمل أو استخدم معرض الأعمال على مستقل

## Mini example (أعد كتابته لكل مشروع)

```text
السلام عليكم،
أنا مطور واجهات أمامية أعمل يوميًا على React و Next.js و Angular، ومنها واجهات حجز وتسعير في بيئة B2B بحجم تشغيل مرتفع.

لماذا أنا مناسب لمشروعك:
• خبرة في بناء وتطوير واجهات تعتمد على REST مع حالات تسعير/حجز معقّدة.
• تنفيذ ترحيل واجهات وتحديثات Next.js مع اهتمام بـ SSR والأداء.
• TypeScript وتنظيم كود قابل للصيانة والتسليم على مراحل.

أقترح نبدأ بتوضيح نطاق الشاشات والـ API، ثم تسليم جزء أولي تراجعونه بسرعة قبل إكمال بقية العمل.

جاهز للنقاش داخل المشروع — ما هي الشاشة أو الميزة الأهم بالنسبة لكم أولًا؟
```

## Bidding notes

- Stay inside the published budget range when possible.
- If the range is too low for the scope: either **Skip** or ask the user before bidding low.
- Duration: honest; slightly conservative better than unrealistically fast.
