# Upwork proposal guide

Read [`../../candidate-source.md`](../../candidate-source.md), then write proposals only from the current `resume.tex`. Short, specific, scannable.

## Length

~120–220 words unless the job asks for a longer cover letter.

## Structure

1. **Hook (1–2 sentences):** Mirror their problem (stack + outcome), not a bio dump.
2. **Proof (2–3 bullets or short lines):** Example Travel Platform B2B aviation booking / Angular migration / Next.js SSR–Web Vitals / relevant freelance or project — only what maps to this JD.
3. **Plan (2–4 steps):** How you’d start in week one (clarify scope → audit UI/API contracts → ship vertical slice → iterate).
4. **Close:** Availability + soft ask (quick call or first milestone). One question max if a screening gap matters.

## Tone

- Professional, direct, confident — not salesy
- Use the language required by the job; do not claim a proficiency level unless it appears in the `.tex` or the user provides it

## Writing voice (required)

Follow [../../website-apply-loop/writing-voice.md](../../website-apply-loop/writing-voice.md). Verbatim rules:

Mix sentence lengths: Combine short, punchy sentences with longer, multi-clause ones instead of keeping every sentence uniform.

Add specific details: Swap abstract, clinical terms for concrete examples, textures, or real-world scenarios.

Vary paragraph structure: Break up predictable paragraph sizes and avoid using a textbook topic sentence for every single paragraph.

Write conversationally: Read your text out loud and replace stiff, formal phrasing with words you would actually say out loud.

Cut the fluff: Remove redundant transitions, repetitive over-explanations, and unnecessary summaries.

## Never

- Fake years, fake clients, fake metrics
- Paste the same generic template unchanged
- Dump the full CV
- Promise timelines you cannot know
- Put external URLs if Upwork flags them in that field — describe instead or use allowed portfolio items

## Screening questions

Answer truthfully. If the form asks for a tool you don’t know: say learning approach + adjacent experience, or ask the user before submit if it would misrepresent.

## Mini example (shape only — rewrite per job)

```text
Hi — I build production React/Next.js and Angular UIs, including B2B booking flows with complex pricing and supplier edge cases.

Relevant fit for this role:
• Own frontend behavior for high-volume search/booking-style workflows on a B2B aviation platform (Angular + REST).
• Shipped Next.js SSR / performance work and modular frontend migrations in freelance projects.
• Strong TypeScript, RxJS/Redux, and API-driven UI delivery.

If we work together I’d start by clarifying success criteria and API contracts, then deliver a thin vertical slice you can review quickly.

Happy to walk through an approach on a short call — what is the highest-priority screen or flow to improve first?
```
