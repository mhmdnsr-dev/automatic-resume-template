# Employment application guide

Read `../candidate-source.md`, the current `resume.tex`, and the full JD before filling anything.

## Full JD first

Before scoring or applying, expand truncated postings (**… more** / **Show more** / equivalent). Score and tailor only from the full visible JD.

## Form rules

- Candidate facts: current master `.tex` only (facts); tailored copy may rephrase/reorder for the JD.
- JD facts: live posting only (fully expanded).
- Unknown required candidate field: ask the user; never infer.
- Resume on **Apply**: run [../jd-fit-resume/SKILL.md](../jd-fit-resume/SKILL.md) → local `yyyy-mm-dd_company-role/` package. Upload the tailored PDF by default. Generate/upload DOCX only when the destination or user explicitly requires Word. Do not overwrite the master or invent experience.
- Existing answers/autofill are untrusted until checked against the `.tex`.
- Legal declarations and consent checkboxes: read them; stop when meaning is unclear.

## Cover letter

On Apply, `cover-letter.txt` comes from [jd-fit-resume](../jd-fit-resume/SKILL.md). Paste it when the form requests a letter or when it materially strengthens the application.

Suggested shape (not boilerplate):

1. One concrete sentence linking the role’s product/stack to a matching CV result.
2. Two or three compact proof points from current Example Travel Platform/freelance/project work.
3. A short first-step approach grounded in the JD.
4. A direct close. One useful question at most.

No fake enthusiasm, generic company praise, unsupported years, salary/availability promises, or copied job-description wording.

## Screening questions

- Technical question: answer from the `.tex`; disclose adjacent experience when the exact tool is absent.
- Years: use the CV’s exact statement/dates; do not round up.
- Salary and notice period: follow the explicit preferences in [`../candidate-source.md`](../candidate-source.md). Current and expected salary stay blank when optional and use `0` when mandatory; notice period is `30 days`. Ask only if the form rejects these answers or forces a different declaration.
- Availability, work authorization, relocation, and language proficiency: ask the user if required.
- Demographic/EEO questions: leave optional fields unanswered when allowed; ask if required.
- Portfolio: use only CV links and only where the platform permits.

## Submission checklist

1. Correct job/company/site and no duplicate application.
2. Every candidate claim traceable to `.tex`.
3. Contact details and dates match `.tex`.
4. Correct resume attached (job-folder tailored PDF by default; tailored DOCX only when explicitly required, after Apply OK).
5. No unsupported dropdown answer or stale autofill.
6. User gave **Apply now?** approval for this exact job.
7. Submit once; verify confirmation.
8. Ask: **Do we continue with the same site or move to another?**
